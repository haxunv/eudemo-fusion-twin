# Runtime contract

The Windows HTTP service listens on 127.0.0.1:8765. It serves the browser application and owns state validation. Kit consumes atomic `runtime/state.json` snapshots and reports `runtime/renderer.json`. No cloud inference is used.

`GET /api/state` returns `{revision,state,result,renderer}`. `POST /api/state` accepts a partial state object. `GET /api/manifest` returns the asset manifest. `POST /api/action` publishes `{type,...}` in a single latest-command slot for Kit; the current implementation does not guarantee execution of rapid consecutive actions. `GET /api/preview.png` returns the latest actual RTX capture. `GET /api/export` returns a provenance-bearing state JSON.

Renderer `resolution` is the fixed 2560×1440 stream/output size. `render_resolution` is the actual viewport texture size: 1920×1080 during camera motion or timeline playback, 2560×1440 after 0.75 seconds without camera motion. `quality` is `interaction` or `detail`. Captures request the full detail resolution. The `fps` field measures Kit update events, not browser presentation; browser performance must be measured with video frame callbacks and WebRTC statistics.

Export provenance contains `manifest_source` (the scene manifest's `source`) and `source_record` (the complete `assets/source/provenance.json`, including upstream commits, licensing notes and file hashes). The browser downloads this server response without replacing the source record.

States: view=overview/front/top/section/divertor; mode=assembly/temperature/heatflux/magnetic/slice; tab=explore/compare; scenario=nominal/ramp/lowflow/highload; power=500..2600 MW; flow=0.4..1.4 (nominal flow ratio); inlet=200..400 °C; phase=0..1; cutaway=0..180 degrees (20-degree sectors); explode=0..1; opacity=0.1..1; visible={component:bool}; selected=component id; fieldLines/orbit/playing=bool.

The compute service writes `runtime/fields.npz` and `runtime/fields.json` before publishing a revision. Field arrays: surface_points(N,3), surface_triangles(M,3), surface_regions(N), surface_triangle_component(M), surface_temperature_C(N), surface_heatflux_MW_m2(N), temperature_rgb(N,3), heatflux_rgb(N,3), magnetic_lines(L,P,3), slice_points(K,3), slice_triangles(J,3), slice_rgb(K,3), slice_temperature_keV(K). Region 0 is blanket; region 1 is divertor. The surface geometry is a single 20-degree CAD sector, replicated about Z by the renderer. The slice and magnetic curves are in world coordinates, metres.

The thermal boundary conditions are synthetic and reproducible. Surface temperatures use a steady thermal-resistance model with a prescribed transient response factor. The surface heat-flux distribution is not area-normalized to a conservative full-reactor power solution; the helium-loop energy balance is a separate demonstration assumption. Magnetic streamlines integrate the stored Bluemira equilibrium using RK4 and the approximation Bphi=fvac/R. Plasma slice temperature is a synthetic profile shaped by source normalized poloidal flux. CUDA timings measure launch plus synchronized kernel execution, excluding host transfer, serialization, and rendering. This is an engineering visualization demonstrator, not validated reactor design analysis.
